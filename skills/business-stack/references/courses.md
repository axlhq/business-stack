# Courses, membership and community

## Fits

- Online courses: lessons with text, hosted video, images and files; tests with auto-grading; homework with optional AI review against the author's instructions; certificates.
- Drip by enrolment day, weekday, cohort start or prerequisite; access that expires; cohorts.
- Selling a course, a plan, a library or a bundle through products and checkout.
- Community: spaces in sections, view/comment/publish permissions set by CRM filters, paid access through subscriptions, one login with the courses. One community per account.

Not a fit: SCORM packages, an app-store app, or automatic import of a course from another platform (lessons, video and tests are rebuilt).

## Settle first

- Structure: modules and lessons, and where the content comes from (their text, documents, videos).
- Access: free, paid, cohort, drip schedule, expiry.
- Tests, homework review and a certificate, if wanted.
- Draft for review, or published.

## Build

Discover live. Today the path is `create_course`, `create_lesson`, `set_lesson_content`, `configure_lesson`, `configure_course`, then `sell_a_course` or `grant_course_access_to_contact`.

- Lesson theory HTML needs the guide token like page HTML.
- Lessons start as drafts. Publishing a course is a separate step and needs the publish permission.
- Creating content, publishing it, putting it in a product and granting someone access are four separate actions. Do only the ones the person asked for.
- Videos: upload them first. See [webinars-and-video](webinars-and-video.md).
- Keep auto-graded tests and AI homework review apart when describing the course.
- Community spaces and permissions are in the communications area of `capability_map`.

## Hand back

Admin links to the course and lessons, what is published, the product or checkout link if it is for sale, and who has access.
